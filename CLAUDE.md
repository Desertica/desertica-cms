# Desertica CMS

Strapi 5 (TypeScript) backend for the Desertica website and its internal content tools. The Angular frontend is `Desertica/desertica-web`; it reads this CMS on the server and keeps static defaults for everything. Read `README.md` (setup), `CONTRACT.md` (the fields the frontend depends on) and `docs/DEPLOY.md` (deployment).

## Commands

```bash
npm install && cp .env.example .env   # fill the secrets (cloud sessions do this in a SessionStart hook)
npm run develop                        # http://localhost:1337/admin, first run seeds an empty database
npm run typecheck && npm run build     # what CI runs
npm run seed-check
```

Use **Node 22**. Create the first admin with `npx strapi admin:create-user ...` or through `/admin`.

## Model

Admin sidebar groups: `Site` (settings, theme, booking rules, forms, navigation), `Catalog` (destination, tour), `Copy` (translation), `Media` (slot), `Pages`, `Blog`, `Shop`, `Inbox` (reservation, contact message). Locales: `en` (default) and `es`. `translation` and `media-slot` rows are segmented by `page` and `section`.

## Rules

- API ids (`singularName`, `pluralName`, uid) and field names are a contract with the frontend mapper; changing one needs a matching change in `desertica-web` (`src/app/core/cms/`) and in `CONTRACT.md`.
- `seed/catalog.json` is generated by `scripts/build-cms-seed.mjs` in the frontend repo (`npm run cms:seed` there); never hand-edit it. Seeding only runs on an empty database.
- Content tied to tours or destinations lives in their own fields; do not duplicate it as `translation` rows.
- `populate=*` does not reach media inside components; use explicit populate paths (see `CONTRACT.md`).
- The Public role only has read access plus create-only for `reservation` and `contact-message`. Keep it that way.
- Never commit `.env`, `.tmp/` or `public/uploads/*`.

## Pitfalls

- The rate limiter keys on IP; behind the frontend's forms proxy it needs the same `FORMS_PROXY_SECRET` on both sides.
- Content Manager list layouts are applied once at bootstrap (`CM_CONFIG_VERSION` in `src/index.ts`); bump it to reapply.
- Theme colors are hex strings from the official color picker custom field (`plugin::color-picker.color`, regex `^#[0-9a-fA-F]{6}([0-9a-fA-F]{2})?$`); fonts, radius and header size are enumerations. Edit-view layouts and hints for `theme-setting` and `theme.palette` live in `EDIT_LAYOUTS`/`COMPONENT_CONFIGS` in `src/index.ts`. The seed converts the frontend's oklch values to hex in `build-cms-seed.mjs`.
