# Desertica CMS

Strapi 5 (TypeScript) backend for the Desertica website and its internal content tools. The Angular frontend is `Desertica/desertica-web`; it reads this CMS on the server and keeps static defaults for everything. Read `README.md` (setup), `CONTRACT.md` (the fields the frontend depends on) and `docs/DEPLOY.md` (deployment).

## Commands

```bash
cp .env.example .env && npm ci   # fill the secrets (cloud sessions do this in a SessionStart hook)
npm run develop                        # http://localhost:1337/admin, first run seeds an empty database
npm run typecheck && npm test && npm run build   # what CI runs
npm run seed-check
```

Use **Node 22**. Create the first admin with `npx strapi admin:create-user ...` or through `/admin`.

## Model

The admin is for Spanish-speaking editors: sidebar names (`displayName` in each `schema.json`), field labels, hints and form layouts are in Spanish. Sidebar groups: `Sitio` (datos de la empresa, colores y estilo, reglas de reserva, formularios, menús), `Catálogo` (destino, tour), `Textos` (texto de la web), `Medios` (imagen o video de la web), `Páginas`, `Blog`, `Tienda`, `Bandeja` (solicitud de reserva, mensaje de contacto). Labels and hints live in `src/admin-es.ts` and layouts in `EDIT_LAYOUTS` in `src/content-manager.ts`; they change only what the editor sees, never an API id or field name. Locales: `en` (default) and `es`. `translation` and `media-slot` rows are segmented by `page` and `section`.

## Rules

- API ids (`singularName`, `pluralName`, uid) and field names are a contract with the frontend mapper; changing one needs a matching change in `desertica-web` (`src/app/core/cms/`) and in `CONTRACT.md`.
- `seed/catalog.json` is generated by `scripts/build-cms-seed.mjs` in the frontend repo (`npm run cms:seed` there); never hand-edit it. The catalog is seeded once on a database that was never seeded (`catalog-seeded` mark in the store); the legal pages are seeded as drafts. What runs on every boot, in order: `ensureLocales`, `grantPublicPermissions`, `restrictEditorRole` (once), `configureContentManager` (until `CM_CONFIG_VERSION` is applied without errors), `seedCatalog` (honors `SEED_ON_EMPTY`), `syncNewTranslations`, `ensureExtraPages` (once).
- Content tied to tours or destinations lives in their own fields; do not duplicate it as `translation` rows.
- `populate=*` does not reach media inside components; use explicit populate paths (see `CONTRACT.md`).
- The Editor role (set once by `restrictEditorRole`) edits and publishes tours, destinations, pages, blog, products, texts and media in `en`/`es`; only a Super Admin deletes tours, destinations and pages, and the Editor has no access to `Bandeja` nor `Sitio`. `scripts/verify-editor.mjs` checks it in CI.
- The Public role only has read access plus create-only for `reservation` and `contact-message`. Keep it that way.
- Never commit `.env`, `.tmp/` or `public/uploads/*`.

## Pitfalls

- Long texts (`page.body`, `blog-post.content`, `product.details`, `tour.waiverBody`) use the CKEditor 5 custom field with the Markdown preset: the stored value is still Markdown. The edit-view panel "Traducción automática" (`src/admin/translate-panel.tsx`, `src/translate.ts`) needs `DEEPL_API_KEY` and only ever saves drafts; pages (legal texts) and `tour.waiverBody` are never sent to DeepL.
- The rate limiter keys on IP; behind the frontend's forms proxy it needs the same `FORMS_PROXY_SECRET` on both sides.
- Content Manager list layouts, labels and hints are applied once at bootstrap (`CM_CONFIG_VERSION` in `src/content-manager.ts`); bump it to reapply. A field missing from an `EDIT_LAYOUTS` entry disappears from the form, so list every field of the type (a test compares each `schema.json` with the layouts). The panel look (Spanish locale, olive theme, logos) is `src/admin/app.tsx`.
- Theme colors are hex strings from the official color picker custom field (`plugin::color-picker.color`, regex `^#[0-9a-fA-F]{6}([0-9a-fA-F]{2})?$`); fonts, radius and header size are enumerations. Edit-view layouts and hints for `theme-setting` and `theme.palette` live in `EDIT_LAYOUTS`/`COMPONENT_LAYOUTS` in `src/content-manager.ts` and `src/admin-es.ts`. The seed converts the frontend's oklch values to hex in `build-cms-seed.mjs`.

## Ramas

`main` es solo la base; el trabajo entra por PR a `develop`, `develop` -> `staging` (pruebas) y `staging` -> `prod` (producción). Rama de trabajo: `feat/*`, `fix/*` o `chore/*`, se borra al mezclar. Los checks y la protección están en `docs/PROTECCION-RAMAS.md`; los workflows son `.github/workflows/{ci,security,policy}.yml` y los editas con un PR normal.
